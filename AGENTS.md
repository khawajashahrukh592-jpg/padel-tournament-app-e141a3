# AGENTS.md

Padel Friday — TanStack Start + React 19 + Tailwind 4 app on Netlify. Roadmap: see **PLAN.md**.

## Architecture
- `src/engine/` — pure, deterministic tournament logic (no React/I/O). `scheduler.ts` picks players and pairings, `history.ts` builds fairness history, `standings.ts`, `scoring.ts`, `tournament.ts` (immutable actions that return a new Tournament and bump `version`). Tests: `engine.test.ts`.
- `src/lib/session-store.tsx` — React context holding the live session; `apply(action)` runs engine actions and toasts `TournamentError`s. Its API is what the future persistence layer should implement so screens don't change.
- `src/lib/fixtures.ts` — the only place with demo data (generated by the engine with a fixed time so SSR matches hydration).
- `src/components/padel/` — app shell, court card (score entry/swap), standings table, round summary, segmented/stepper controls.
- `src/routes/` — `/`, `/setup`, `/live`, `/standings`, `/matches`, `/history`, `/settings`.

## Conventions / decisions
- Scheduling must stay deterministic (seeded hashing) so every viewer computes identical schedules.
- Only the latest unstarted round is regenerated; completed rounds are never mutated except via explicit score edits.
- Mexicano ranking uses average points per match so rests don't penalise players.
- Theme colors in `src/styles.css` (`ball`, `court` tokens); fonts Barlow Condensed + Manrope.
- Host/viewer is currently a client-side toggle only — real auth is a planned milestone.
